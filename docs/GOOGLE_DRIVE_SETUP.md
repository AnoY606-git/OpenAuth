# Подключение личного Google Drive

Open Auth хранит копии в скрытой области `appDataFolder` **личного Google-аккаунта пользователя**. Подключение добровольное; файловые копии и локальные коды работают без Google. Проект Google Cloud регистрирует приложение разработчика один раз. Пользователям не нужно создавать проект, оплачивать аккаунт разработчика или передавать пароли Google в Open Auth. Собственный сервер не используется.

Перед отправкой приложение шифрует снимок локально. Фоновая задача получает только готовый зашифрованный файл. Пароль или PIN копии потребуется при восстановлении; Google не может восстановить забытый пароль копии. После системного выбора аккаунта или согласия Google приложение может быть заблокировано. Явно разблокируйте его и настройте пароль копии, если он ещё не задан: до этого первая отправка ожидает готового снимка.

## Однократная настройка разработчиком

1. Создайте проект в [Google Cloud Console](https://console.cloud.google.com/) и включите Google Drive API.
2. Настройте Google Auth Platform: сведения о приложении, аудиторию, контакт разработчика и экран согласия. Для режима Testing добавьте адреса тестовых пользователей. Выпуск для других пользователей требует соответствующей настройки публикации и выполнения актуальных требований Google.
3. Создайте OAuth client типа **Android**: package name `dev.openauth.app` и SHA-1 сертификата, которым подписан устанавливаемый APK. Для другой подписи нужен соответствующий Android client. Debug, собственный release и Play App Signing могут иметь разные сертификаты.
4. Получите SHA-1 установленной сборки через Android SDK `apksigner verify --print-certs <apk>` либо `./gradlew :app:signingReport` для локального варианта. Не подставляйте отпечаток upload key вместо сертификата Play App Signing, если APK подписывается Google Play.
5. Приложение запрашивает единственный OAuth scope `https://www.googleapis.com/auth/drive.appdata`. Не нужны Web client secret, `requestOfflineAccess`, refresh token или backend. Android OAuth client сопоставляется Google с package и подписью приложения.
6. Установите подписанную сборку на Android 12+ с Google Play services. Подключите тестовый аккаунт через системный выбор и согласие Google. До выполнения этой настройки локальные тесты не подтверждают работоспособность живого OAuth.

Публикация APK через Google Play — отдельный процесс, не условие локальной установки или регистрации OAuth Android client. Условия квот и тарификации Drive API проверяйте в [официальных ограничениях](https://developers.google.com/workspace/drive/api/guides/limits); эта инструкция не обещает неограниченное бесплатное использование сервиса.

## Работа с копиями

После подключения создаётся полный снимок, когда хранилище разблокировано и задан пароль или PIN копии. Изменения сохраняются автоматически при доступной разблокированной сессии. Фоновая отправка требует сети; во время блокировки она может отправить уже готовый шифротекст, но не создать новый снимок. Повторная отправка использует сохранённый идентификатор файла. История ограничена десятью подтверждёнными снимками на установку приложения; копии другого телефона не очищаются автоматически.

Отключение отменяет новые отправки и сохраняет уже загруженные копии. Смена Google-аккаунта создаёт новое назначение: выполнявшаяся отправка может завершиться в старом аккаунте, но её результат не считается копией в новом. Удаление истории — отдельное действие с подтверждением, ограниченное снимками этой установки в выбранном аккаунте.

Для восстановления выберите снимок из истории аккаунта, затем в локальном экране восстановления введите пароль или PIN и проверьте предварительный результат объединения или замены. Выбор и скачивание ещё не меняют коды. Файл копии зашифрован; данные проверяются локально перед применением.

Если Google Play services отсутствуют, используйте файловые копии. Если доступ отозван, откройте подключение Google и подтвердите доступ заново; фоновые задачи не показывают окно согласия. Ошибка настройки package, подписи, аудитории или Drive API не считается успешным подключением.

## Проверка перед распространением

Проверьте на реальных Google-аккаунтах: первую копию заполненного хранилища, восстановление на другой установке, отказ от согласия, отзыв доступа, отсутствие сети и её возвращение, смену аккаунта во время отправки, отдельное удаление истории своей установки. JVM и MockWebServer проверяют локальные контракты, но не заменяют эти проверки Google.

Первичные источники: [AuthorizationClient](https://developers.google.com/identity/authorization/android), [ограниченное хранилище приложения](https://developers.google.com/workspace/drive/api/guides/appdata), [создание OAuth credentials](https://developers.google.com/workspace/guides/create-credentials).
