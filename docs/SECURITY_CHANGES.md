# Исправления защиты счётчиков и резервных копий

## HOTP

Приложение хранит максимум следующего HOTP-счётчика отдельно от карточки
аккаунта. Удаление последнего псевдонима, переключение HOTP/TOTP, смена
6/8 цифр и восстановление старой копии на том же доступном хранилище не
сбрасывают уже известный максимум. Карточки одного секрета с разной длиной
кода используют общий счётчик; параметры отображения и дедупликации остаются
раздельными.

После удаления карточки остаются только доменно-разделённый SHA-256
отпечаток и счётчик внутри шифротекста, без исходного удалённого секрета.
История не вытесняется автоматически; её переполнение безопасно останавливает
операцию. Новая установка не может знать использование после даты старой
копии. Историю, потерянную до обновления, восстановить невозможно.

## Совместимость

Старые `.oab` и хранилища схемы 1 читаются. Ненулевая история HOTP сохраняется
по схеме 2 зашифрованного JSON; бинарный контейнер и криптографический профиль
не изменены. **OpenAuth 1.0.0 не сможет открыть схему 2.** После обновления
не откатывайте APK без заранее проверенной старой копии. Новые копии
с историей нужно открывать новой версией приложения. Прежде чем обновлять
основное устройство, сохраните и проверьте отдельную резервную копию.

## Другие изменения

- Лимит групп — 10000. Модель, потоковый JSON-декодер и MERGE проверяют
  ограничение; список групп-фильтров выводится лениво.
- При задании или смене пароля/PIN копии обязателен повторный совпадающий
  ввод. При восстановлении второй ввод не требуется. Оба поля очищаются
  при смене режима, отмене и уходе в фон.
- После финального rename аварийного восстановления синхронизируется
  родительский каталог. Если barrier завершается ошибкой после установки,
  уже установленный Keystore-ключ и прежний ciphertext сохраняются.
- Тест политики Git-индекса работает в Windows без создания запрещённых
  имён файлов; разбор NUL и переводов строк проверяется отдельно.

Проверены опубликованные AAR metadata выбранных основных артефактов:
они не требуют подъёма compileSdk 36 или AGP 8.13.2. Полная совместимость
всего транзитивного графа проверяется Android CI.

Compose BOM 2026.09.00 не выбран: его UI 1.12.1 требует compileSdk 37 и
AGP 9.1.0. То же ограничение имеют Compose-модули Lifecycle 2.11.0;
используется согласованная линейка Lifecycle 2.10.0. Serialization 1.10/1.11 требует Kotlin 2.3; текущая версия Kotlin
2.2.21 сохранена. OkHttp/MockWebServer остаются на совместимой ветке 4.12.0:
переход на 5.x — отдельное изменение API и тестового стека. Biometric 1.1.0
и Play Services Auth 22.0.0 остаются текущими стабильными в проверенных
метаданных. Изменение AGP/Kotlin/SDK и публикация подписанного APK в этот
набор исправлений не входят.
